一、认证模块
================================================================================

【用例1.1】用户登录
------------------
接口地址：POST /api/auth/login
请求头：
  Content-Type: application/json

请求体：
{
  "username": "admin",
  "password": "admin123"
}

预期响应（成功）：
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userInfo": {
      "userId": 1,
      "username": "admin",
      "nickName": "系统管理员",
      "avatar": ""
    },
    "permissions": ["*:*:*"]
  }
}

测试步骤：
1. 发送POST请求到 /api/auth/login
2. 在请求体中填入用户名和密码
3. 获取返回的token，保存用于后续请求
4. 验证返回状态码为200
5. 验证返回数据中包含token和userInfo

【用例1.2】用户登出
------------------
接口地址：POST /api/auth/logout
请求头：
  Authorization: Bearer {token}
  Content-Type: application/json

请求体：无

预期响应（成功）：
{
  "code": 200,
  "msg": "操作成功",
  "data": null
}

测试步骤：
1. 使用登录获取的token
2. 发送POST请求到 /api/auth/logout
3. 验证返回状态码为200

================================================================================
七、错误场景测试
================================================================================

【用例7.1】未授权访问
-------------------
接口地址：GET /api/purchase/requisition/page
请求头：无（不包含Authorization）

预期响应（失败）：
{
  "code": 401,
  "msg": "未授权，请先登录",
  "data": null
}

测试步骤：
1. 不提供token
2. 发送GET请求到需要认证的接口
3. 验证返回状态码为401
4. 验证返回错误信息

【用例7.2】无效token
-------------------
接口地址：GET /api/purchase/requisition/page
请求头：
  Authorization: Bearer invalid_token_12345

预期响应（失败）：
{
  "code": 401,
  "msg": "Token无效或已过期",
  "data": null
}

测试步骤：
1. 使用无效的token
2. 发送GET请求到需要认证的接口
3. 验证返回状态码为401
4. 验证返回错误信息

【用例7.3】权限不足
-------------------
接口地址：POST /api/purchase/requisition
请求头：
  Authorization: Bearer {token} (使用普通用户token，如inventory_manager)

预期响应（失败）：
{
  "code": 403,
  "msg": "没有访问权限",
  "data": null
}

测试步骤：
1. 使用没有采购权限的用户登录（如inventory_manager）
2. 获取token
3. 尝试访问采购模块的创建接口
4. 验证返回状态码为403
5. 验证返回权限不足的错误信息

【用例7.4】参数验证失败
-----------------------
接口地址：POST /api/auth/login
请求头：
  Content-Type: application/json

请求体：
{
  "username": "",
  "password": ""
}

预期响应（失败）：
{
  "code": 400,
  "msg": "用户名不能为空",
  "data": null
}

测试步骤：
1. 发送登录请求，但用户名或密码为空
2. 验证返回状态码为400
3. 验证返回参数验证错误信息

【用例7.5】资源不存在
--------------------
接口地址：GET /api/asset/99999
请求头：
  Authorization: Bearer {token}

预期响应（失败）：
{
  "code": 404,
  "msg": "资源不存在",
  "data": null
}

测试步骤：
1. 使用不存在的资源ID
2. 发送GET请求
3. 验证返回状态码为404
4. 验证返回资源不存在的错误信息

================================================================================
十、Postman使用技巧
================================================================================

1. 设置环境变量
   - 创建环境：智慧煤矿ERP
   - 添加变量：
     * base_url: http://localhost:8080
     * token: (从登录接口获取后自动设置)

2. 使用Pre-request Script自动获取token
   - 在需要token的请求前，先执行登录请求
   - 使用脚本提取token并设置到环境变量

3. 使用Tests脚本验证响应
   - 验证状态码：pm.response.to.have.status(200)
   - 验证响应体：pm.response.to.have.jsonBody('code', 200)
   - 提取数据：var token = pm.response.json().data.token

4. 使用Collection Runner批量执行
   - 创建测试集合
   - 使用Collection Runner批量执行所有测试用例
   - 查看测试报告
