三、接口测试步骤（使用Postman）
================================================================================

【步骤1：用户登录获取Token】

1. 打开Postman，创建新请求
2. 请求方法：POST
3. 请求URL：http://localhost:8080/api/auth/login
4. 请求头（Headers）：
   Content-Type: application/json
5. 请求体（Body，选择raw + JSON）：
   {
     "username": "admin",
     "password": "admin123"
   }
6. 点击Send发送请求
7. 查看响应结果，复制返回的token值

【步骤2：设置全局Token】

1. 在Postman中点击右上角"环境变量"或"变量"
2. 创建新环境变量：
   - 变量名：token
   - 初始值：从步骤1获取的token值
3. 在后续请求的Headers中添加：
   Authorization: Bearer {{token}}

【步骤3：测试采购申请查询接口】

1. 创建新请求
2. 请求方法：GET
3. 请求URL：http://localhost:8080/api/purchase/requisition/page?current=1&size=10
4. 请求头：
   Authorization: Bearer {{token}}
5. 点击Send，查看返回的分页数据

【步骤4：测试创建采购申请】

1. 创建新请求
2. 请求方法：POST
3. 请求URL：http://localhost:8080/api/purchase/requisition
4. 请求头：
   Authorization: Bearer {{token}}
   Content-Type: application/json
5. 请求体（示例）：
   {
     "requisition": {
       "requisitionNo": "CG20240101001",
       "requisitionDate": "2024-01-01",
       "requisitionDept": "采购部",
       "requisitionUser": "张三",
       "remark": "测试采购申请"
     },
     "details": [
       {
         "materialCode": "MAT001",
         "materialName": "测试物料",
         "quantity": 100,
         "unit": "件",
         "estimatedPrice": 50.00
       }
     ]
   }
6. 点击Send，查看创建结果

【步骤5：测试权限控制】

1. 使用普通用户（如purchase_manager）登录获取token
2. 尝试访问其他模块的接口（如维修管理接口）
3. 验证是否返回权限不足的错误

四、接口测试步骤（使用curl命令）
================================================================================

【Windows PowerShell 或 Linux/Mac 终端】

步骤1：用户登录
--------------
curl -X POST http://localhost:8080/api/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"admin\",\"password\":\"admin123\"}"

（Linux/Mac使用反斜杠 \ 而不是 ^）

步骤2：保存Token（假设返回的token为：eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...）
--------------
# Windows PowerShell
$token = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

# Linux/Mac
export TOKEN="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

步骤3：测试查询接口
--------------
# Windows PowerShell
curl -X GET "http://localhost:8080/api/purchase/requisition/page?current=1&size=10" ^
  -H "Authorization: Bearer $token"

# Linux/Mac
curl -X GET "http://localhost:8080/api/purchase/requisition/page?current=1&size=10" \
  -H "Authorization: Bearer $TOKEN"

步骤4：测试创建接口
--------------
# Windows PowerShell
curl -X POST http://localhost:8080/api/purchase/requisition ^
  -H "Authorization: Bearer $token" ^
  -H "Content-Type: application/json" ^
  -d "{\"requisition\":{\"requisitionNo\":\"CG20240101001\",\"requisitionDate\":\"2024-01-01\",\"requisitionDept\":\"采购部\"},\"details\":[{\"materialCode\":\"MAT001\",\"materialName\":\"测试物料\",\"quantity\":100}]}"

五、性能测试演示（使用JMeter）
================================================================================

【演示目标】
1. 测试系统并发处理能力
2. 测试接口响应时间
3. 测试系统吞吐量
4. 发现性能瓶颈

【测试场景设计】

场景一：登录接口压力测试
------------------------
1. 线程组设置：
   - 线程数：50（模拟50个并发用户）
   - Ramp-up时间：10秒（10秒内启动50个线程）
   - 循环次数：10（每个线程执行10次）

2. HTTP请求：
   - 方法：POST
   - 路径：/api/auth/login
   - 参数：username=admin&password=admin123

3. 监听器：
   - 查看结果树（查看请求响应）
   - 聚合报告（查看统计信息）
   - 图形结果（查看性能曲线）

场景二：查询接口并发测试
------------------------
1. 先执行一次登录，获取token
2. 使用HTTP Header Manager添加Authorization头
3. 线程组设置：
   - 线程数：100
   - Ramp-up时间：20秒
   - 循环次数：20

4. HTTP请求：
   - 方法：GET
   - 路径：/api/purchase/requisition/page?current=1&size=10

场景三：混合场景测试
--------------------
1. 创建多个线程组：
   - 线程组1：登录接口（20%）
   - 线程组2：查询接口（50%）
   - 线程组3：创建接口（30%）

2. 使用吞吐量控制器分配比例

【JMeter操作步骤】

步骤1：创建测试计划
------------------
1. 打开JMeter
2. 右键"测试计划" -> 添加 -> 线程（用户） -> 线程组

步骤2：配置线程组
------------------
1. 线程数：50
2. Ramp-up时间：10
3. 循环次数：10

步骤3：添加HTTP请求
-------------------
1. 右键线程组 -> 添加 -> 采样器 -> HTTP请求
2. 配置：
   - 服务器名称：localhost
   - 端口号：8080
   - HTTP请求：POST
   - 路径：/api/auth/login
   - 参数：username=admin, password=admin123

步骤4：添加监听器
------------------
1. 右键线程组 -> 添加 -> 监听器 -> 查看结果树
2. 右键线程组 -> 添加 -> 监听器 -> 聚合报告
3. 右键线程组 -> 添加 -> 监听器 -> 图形结果

步骤5：运行测试
---------------
1. 点击绿色运行按钮
2. 观察监听器中的结果
3. 查看聚合报告中的关键指标：
   - 样本数（请求总数）
   - 平均值（平均响应时间）
   - 中位数（50%请求的响应时间）
   - 90%百分位（90%请求的响应时间）
   - 最小值/最大值
   - 错误率
   - 吞吐量（每秒请求数）

六、性能测试演示（使用Apache Bench - ab）
================================================================================

【Apache Bench是Apache HTTP服务器自带的性能测试工具】

步骤1：安装Apache Bench
-----------------------
- Windows：下载Apache HTTP Server，ab.exe在bin目录
- Linux：通常已安装，命令为 ab
- Mac：通常已安装

步骤2：测试登录接口
-------------------
ab -n 1000 -c 50 -p login.json -T application/json http://localhost:8080/api/auth/login

参数说明：
- -n 1000：总共发送1000个请求
- -c 50：并发数为50
- -p login.json：POST请求的JSON文件
- -T application/json：设置Content-Type
- 最后是目标URL

步骤3：创建login.json文件
-------------------------
{
  "username": "admin",
  "password": "admin123"
}

步骤4：查看测试结果
-------------------
ab会输出以下关键指标：
- Requests per second（每秒请求数）
- Time per request（每个请求的平均时间）
- Transfer rate（传输速率）
- 各种百分位的响应时间

七、测试指标说明
================================================================================

【关键性能指标】

1. 响应时间（Response Time）
   - 平均值：所有请求的平均响应时间
   - 中位数：50%请求的响应时间
   - 90%百分位：90%请求的响应时间
   - 99%百分位：99%请求的响应时间
   - 目标：一般接口 < 500ms，复杂查询 < 2s

2. 吞吐量（Throughput）
   - 每秒处理的请求数（QPS）
   - 目标：根据业务需求，一般 > 100 QPS

3. 错误率（Error Rate）
   - 失败的请求占总请求的百分比
   - 目标：< 1%

4. 并发用户数（Concurrent Users）
   - 同时访问系统的用户数
   - 目标：根据系统设计，一般支持100-1000并发

5. 资源利用率
   - CPU使用率：< 80%
   - 内存使用率：< 80%
   - 数据库连接数：< 最大连接数的80%

九、常见问题与解决方案
================================================================================

问题1：接口返回401未授权
------------------------
原因：Token过期或未正确传递
解决：
1. 重新登录获取新Token
2. 检查请求头中Authorization是否正确
3. 确认Token格式：Bearer {token}

问题2：接口返回403权限不足
--------------------------
原因：当前用户没有该接口的访问权限
解决：
1. 使用有权限的用户登录（如admin）
2. 检查用户角色和权限配置

问题3：性能测试时连接被拒绝
---------------------------
原因：服务器无法处理过多并发请求
解决：
1. 降低并发数
2. 检查服务器配置（线程池、连接池等）
3. 检查数据库连接池配置

问题4：响应时间过长
------------------
原因：可能是数据库查询慢、网络延迟、业务逻辑复杂
解决：
1. 检查数据库索引
2. 优化SQL查询
3. 增加缓存
4. 优化业务逻辑
